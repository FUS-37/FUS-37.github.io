## 前言

由于一些嵌入式开发的需求，我最早开始在Surface Go2上刷了Ubuntu24。这是我第一次使用Linux的系统，丝滑的包管理器和沟槽的输入法，使用体验真的相当的“舒服”。显然Linux的唯一问题就是人要去适应它，在克服了一系列抽象的问题之后，我有点喜欢它了。正好我也打算精进一下编程，所以我给我的笔记本电脑刷了一个双系统。之所以不用虚拟机，是我想看看能不能过渡一下，最后all in Ubuntu。

扯远了，我们来看一下在Ubuntu上进行音乐制作，到底困难在哪里，也可以顺便给出答案：只要你不是那种编程之余写点8bit音乐的音乐人的话，all in Linux，目前来说有点潜力但是并无可能。

## DAW

虽然Linux开源社区里我相信一定能找到不少开源的DAW项目，但是我不认为这有什么意义。这些项目不是太过于极客，就是功能过于有限。如果能够在Linux上使用大家熟悉的工具，这才说明这个方案是成熟的。你可以尝试一下Studio one和reaper。reaper暂且不谈，是的，S1有linux的版本！

但是不好用！奇怪的窗口行为和中文乱码，以及并不好的性能优化。但是不管怎么样，它有Linux的版本已经算是非常出人意料的了。至于reaper，我建议你如果有JUCE开发插件之类的需求，reaper是个不错的测试平台。如果你有游戏音频的开发需求，它也非常不错。

总的来说，在Ubuntu上面进行音乐制作，我们似乎看到了希望。

## 插件与音源

vst格式在Linux上依旧可以使用。你甚至可以在github上下载到很多插件，甚至是一些很有意思的小玩具。但是问题是安装。绝大多数的插件厂家都没有提供linux下的插件程序，音源也是同理。

那开源社区的插件是怎么做的呢？没有安装程序，直接是vst格式的文件，你只需要放到对应的文件夹即可。

我尝试了使用win容器安装插件，再把vst的文件从容器里面拿出来。这个方案在UA connect上失败了。还有一个方案是把vst插件在win上面先安装在外接硬盘上面，再用DAW去扫描，我还没有尝试，你感兴趣可以试试。总的来说，此时已经遇到了巨大的失败，但是还没有完。

2025:11:13： 事实上我发现用wine容器这个思路很早之前有人试过了，你可以看：https://zhuanlan.zhihu.com/p/386163903 我会失败，很大的原因是uad的插件加密过于复杂了。 

## 音频驱动

首先是Linux自带的音频驱动，我有听说过会比win好一些，毕竟很难想象还会有比win更烂的了对吧。但是实际上无论是Linux还是win，音质都并不令人满意。顺便一提在win上面我们还有ASIO，但是Linux我不知道是否会有更好的方案。无论如何，我相信开源社区一定能整出什么好活。

作为一个音乐人，你大概率会有一张独立的外置声卡，好了那么恭喜你，市面上大部分的声卡驱动都没有适合Linux的版本。日常使用很多声卡可以直连，但是在DAW里面，且不说虚拟跳线，你甚至有很大的可能在驱动的控制面板里都无法切换到你的声卡。起码我的羚羊ZenGo是这样。此刻希望彻底破灭，悲伤逆流成河。

2025:11:13： 我收回上面的话，linux的音频驱动真的很棒，绝大多数的声卡都可以免驱动使用，我个人主观感受是很win的asio水平差不多，甚至更好！不过你可能需要自己研究一下linux的音频驱动高级技巧，比如 ALSA 驱动 和 PulseAudio 服务。至于虚拟跳线，建议你使用JACK。

安装和配置 ALSA 驱动
> ALSA 是 Linux 的高级声音架构，确保其已安装并正确配置。

```shell
#示例，不保证仍然有效，请查阅： https://www.alsa-project.org/wiki/Main_Page
sudo apt-get install alsa-utils
alsamixer
```

安装和启动 PulseAudio 服务
>PulseAudio 是常用的声音管理服务。如果未安装或未运行，可以手动安装并启动。

```shell
#示例，不保证仍然有效，请查阅： https://www.freedesktop.org/wiki/Software/PulseAudio/
sudo apt-get install pulseaudio
pulseaudio --start
```

讲个笑话，如果你观察过的话，很多的声卡的驱动都是在asio的基础上做到再开发，而asio是为了绕开win的音频层开发的，这就意味大部分的声卡都没有linux的驱动。well，你完全可以免驱使用，但说这也意味着我们没有办法在linux上使用dsp。实际上说可以的，如果你使用rme的话，它家似乎有在尝试开发在linux上使用的驱动，这就很棒。但是uad和羚羊，不好意思，就没有办法了。

## 总结

上述均是延续了我在win上制作音乐的经验。那么如果说完全抛弃那些经验，拥抱开源社区呢？well，这确实值得探索，部分工具也确实功能强大。但是代价是什么呢？令人困惑的ui，并不流畅的使用体验，一系列过于极客的的意料之外的bug。我喜欢开源社区，总是有很多意外的惊喜，但是在2025年，完全不考虑用户体验是走不远的。何况对于很多音乐人来说，留在舒适区内无忧无虑，才有更多的精力投入到感受和欣赏音乐本身。
